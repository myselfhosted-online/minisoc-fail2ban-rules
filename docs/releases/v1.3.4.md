# MiniSOC Fail2Ban Rules v1.3.4

**Maintenance hotfix — merging existing and new MiniSOC signatures safely**

## Reported failure

During a real Debian v1.3.3 dry run, two customized Fail2Ban filters were correctly preserved, but the updater then stopped at `Invalid regex /etc/minisoc/signatures-v2.db:1: unbalanced parenthesis at position 1`. This came from preflight validation of the **existing local** database, not from any finding that the bundled v1.3.3 signatures were invalid.

## Fix

- Preserve existing signature lines exactly, regardless of whether a legacy regex is compatible with Python's engine. Warn for operator review, rather than reject the old row.
- Merge the old and new signatures into the existing `/etc/minisoc/signatures-v2.db` file, identified by signature ID: append only missing IDs.
- When an existing ID has a different definition, **skip the incoming definition with a warning** and keep the original; no error or duplicate row.
- Always strictly validate bundled signatures. If the old file's record structure is unparseable, preserve it intact and require explicit `--preserve-custom-signatures` for a partial update.
- Make a root-protected backup of the original database before writing its merged form; retain post-write Fail2Ban validation, automatic rollback and preflight checks.

## Upgrade instructions

From the extracted **v1.3.4** archive, first review the plan:

```bash
sudo bash ./install/install.sh --dry-run
```

If the plan reports incompatible custom **Fail2Ban filters** (as in the original Debian report), explicitly preserve those filters while still merging the MiniSOC signatures:

```bash
sudo bash ./install/install.sh --dry-run --preserve-custom-filters
sudo bash ./install/install.sh --preserve-custom-filters
sudo fail2ban-client -t
```

**Important:** Preserving customized Fail2Ban filters does *not* activate new rules in them. MiniSOC signatures are still merged by ID and do not overwrite old definitions. The MiniSOC application is not restarted, and the installer does not claim to repair an unknown live regex. Publishing the release does not deploy it to production.
