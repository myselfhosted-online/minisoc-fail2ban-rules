# MiniSOC Fail2Ban Rules v1.3.5 — unreleased candidate

Database-only upgrades no longer reload Fail2Ban, avoiding disruption to unchanged live jails.

**Compatibility repair for the real MiniSOC signature database format**

## Root cause

The operator's production `/etc/minisoc/signatures-v2.db` contains rows such as `secret|HIGH|/\.env([./? ]|$)`. The running `/opt/minisoc/bin/minisoc-correlator.py` reads them as `kind,sev,pat = raw.split('|', 2)` and compiles `pat` with Python's `re.I` flag. Repeated `secret` and `repository` values are categories, **not duplicate IDs**. Embedded regex `|` alternations are normal.

The public rule source instead uses `id|severity|category|regex`. The v1.3.4 updater incorrectly attempted to read the runtime database as public source rows, leading to the reported `Duplicate signature ID secret` and a non-writing dry-run refusal. Simply disabling the duplicate-ID guard would have risked appending four-column rows unreadable by the actual production correlator.

## Candidate change

- Validate bundled source records, their unique IDs, regexes (`re.I`), and runtime-supported severity levels.
- Convert bundled records to runtime `category|severity|regex` rows before writing the installed file.
- Preserve original local rows and comments byte-for-byte, including repeats of a category and `|` within regexes.
- Skip incoming regex patterns already present locally, preserving the operator's category and severity.
- Preserve a structurally incompatible or explicitly four-column local database for review instead of mixing formats.
- Skip creation of the bundled default jail file if an existing jail definition is found in `jail.local`, `jail.conf`, or a separate `jail.d/*.conf` / `*.local` file, preventing unexpected policy overrides.
- Retain atomic replacement, complete backup, Fail2Ban checks, and automatic rollback; do not restart the MiniSOC application.

## Verification and limits

Offline regression tests now simulate the actual correlator's `raw.split('|', 2)` behavior and the reported multi-category legacy database. They also cover idempotence, customized filter preservation, rollback, CRLF, and patterns containing alternations. The real private production database has not yet been provided or installed in the test environment. Further verification on the operator's Debian host is required before any release.

The existing custom Nginx Fail2Ban filters are still preserved, not updated, when `--preserve-custom-filters` is selected. The installer now checks common alternate jail definitions before proposing a new default jail file; manually review the planned changes before installation, especially if you use an unusual Fail2Ban include layout.

**This is an unpublished review candidate. Do not treat it as a deployed update or an official GitHub Release.**
