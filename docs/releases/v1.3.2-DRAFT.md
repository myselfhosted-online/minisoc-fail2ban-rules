# MiniSOC Fail2Ban Rules — Maintenance and Detection Update (Draft)

## Release rationale

This planned maintenance release addresses update safety, rollback reliability, rule-validation gaps, and false-positive risks identified in the v1.3.1 source audit. It also adds narrowly scoped detection coverage based on reviewed November 2026 incidents, while keeping generic configuration discovery patterns in a non-blocking review category.

## Bugs fixed

1. **Destructive uninstall without recovery:** replaced unconditional file deletion with a fail-closed uninstaller that preserves customized files, backs up project-managed files, validates configuration changes and automatically restores files on failure.
2. **Misleading regex test success:** regression tests now verify that malicious fixtures match and harmless fixtures do not, rather than treating a successful `fail2ban-regex` exit code as proof of detection.
3. **Overly permissive request-target matching:** tightened Nginx detection expressions so benign query parameters containing a suspicious-looking path cannot trigger one-hit bans.
4. **Incomplete backup traceability and recovery:** added manifest-backed backups, original metadata, SHA-256 verification, and an explicit, guarded restore utility.
5. **Unsafe or ambiguous local filter updates:** improved recognized-version baselines, three-way merge checks, local override detection, idempotency and conflict handling.
6. **Insufficient update/uninstall regression coverage:** expanded tests for configuration preservation, backup integrity, rollback, symlinks, manual recovery and cross-jail incident deduplication.
7. **Gaps in developer-secret and IaC exposure detection:** added targeted indicators for Terraform state backup, root OAuth client-secrets file, and `.env` traversal variants, without elevating generic `config.json` and frontend assets to one-hit bans.

## Compatibility and rollout policy

### Additional draft fixes from 18 November evidence

8. **Encoded-secret probes:** included narrow indicators for URL-encoded and double-encoded dot characters and encoded letters targeting the backend .env file; these are not treated as generic directory traversal.
9. **SQL backup discovery:** added exact root database, backup and dump SQL indicators without matching unrelated names or query parameter values.
10. **Inflated alert counts across jails:** incident correlation now separates request entries from duplicated notifications, deduplicated events and distinct raw URL paths.
11. **Missing diagnostic heuristics:** short-window HTTP status changes and equivalence of multiple encoded paths are reported for investigation only, never as independent reasons to ban.
12. **Missing query-driven secret traversal:** exact Nginx request-target rules now cover repeated ../ segments in the userfiles path parameter when targeting .env, plus encoded parent segments under cache/original.
13. **Encoded separator and repository metadata probes:** added precise patterns for encoded slash targeting .env, and encoded question-mark suffixes targeting Git configuration. Broad encoded character patterns remain excluded.
14. **Credential-file exposure coverage:** added exact targets for application service-account.json and Streamlit secrets.toml while leaving normal frontend configuration assets as review-only indicators.
15. **Afternoon regression samples:** included 36 additional denied Nginx request samples across six jail alerts, new benign counterexamples, and intermediate incident statistics for the first five incidents.

16. **Evening alert deduplication:** added seven further jail notifications covering three additional IP sources; one request batch was repeated across three jails, so 42 notification entries correspond to 33 distinct HTTP events.
17. **API file-read and traversal research:** documented targeted `/api/system/fileView`, `/api/fs/read` with `allowOutsideWorkspace=true`, and query-based `/api/console/api_server` probes. They remain review-only until raw Nginx query encoding has been confirmed.
18. **WordPress lookalike classification:** preserved unusual uppercase-I spelling in `/wp-Iogin.php`, plus `/wp-optimizer.php` and an empty `/config.php?` query, as candidate indicators that do not independently trigger bans.
19. **18 November full-day statistics and repeatability:** extended sanitized fixtures to eight parent incidents, 17 jail alerts, 102 displayed entries and 87 deduplicated events (63 HTTP 401 and 24 HTTP 404), with a separate evening synthetic log fixture and regression tests.
20. **19 November credential and backup enumeration research:** added an independent two-jail, 12-request incident with no overlapping events. Existing precise SQL backup and .env indicators cover four of the twelve sample lines in each draft filter; generic JSON/YAML credentials and public-looking JS configuration names remain non-blocking review candidates.
21. **Cross-category burst heuristics:** documented a future diagnostic signal for numerous config, credentials, secrets, SQL backup and frontend env requests from the same source in one short time window. This signal does not change the current ban rules.
22. **19 November second-half evidence:** two new distinct parent incidents cover WordPress PHP reconnaissance and an overlapping two-jail .env/backup scan. The latter repeats six requests in both jail notifications; the correct total for the whole day is 30 displayed requests but 24 unique events across three parent incidents.
23. **20 November repeated cloud-source evidence:** recorded six denied env-file probes from a source seen on 18 November with a different path set. The two days are kept as separate incidents, with cross-day recurrence reported for investigation only.
24. **Review-only detection research:** added scoped candidates for `/wp-xserver.php`, double-slash WordPress locale path, `/site.zip` and `/sendgrid.env`. None is promoted to a standalone Fail2Ban block condition.
25. **21 November duplicate-jail burst:** added a six-request env-file probe repeated verbatim in two jail alerts. The deduplicated incident adds six events, not twelve, and shares the same six-path target set as a separate 20 November cloud-source incident. Cross-source pattern similarity remains a diagnostic lead, not an attribution or ban rule.

New WordPress PHP probes, sensitive file-read APIs, generic secrets JSON/YAML and frontend env.js review paths, CircleCI config discovery and Kubernetes secrets API enumeration remain review-only and require contextual corroboration before promotion. **39 offline regression tests pass**, covering supplied alerts through 21 November; the actual `fail2ban-regex` integration is still required.
