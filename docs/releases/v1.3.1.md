# MiniSOC Fail2Ban Rules v1.3.1

## Release purpose

This maintenance release addresses update-safety and configuration-preservation defects identified during the v1.3.0 rollout. Its primary objective is to make upgrades predictable and reversible while keeping administrator-maintained Fail2Ban rules and MiniSOC signatures intact.

## Bugs fixed

1. **Locally customized Fail2Ban filters could be overwritten.** The installer now recognizes the upstream v1.2.1 and v1.3.0 filters and performs a conservative three-way merge where a supported baseline can be determined. Ambiguous edits or merge conflicts stop the update before any files are changed.
2. **MiniSOC's active signature database was not updated.** The installer now synchronizes `/etc/minisoc/signatures-v2.db` when MiniSOC is installed. New signatures are added by ID without discarding local, operator-defined entries.
3. **Signature ID collisions were not checked.** Existing IDs with conflicting definitions now cause a clear error instead of silently replacing production detection logic.
4. **Local filter overrides could mask updated rules.** The updater detects corresponding Fail2Ban `.local` overrides and stops for administrator review.
5. **Update failures were insufficiently isolated.** Changes are preflighted, backed up, written atomically, validated using `fail2ban-client -t`, and followed by a controlled reload. A validation or reload failure restores the previous files and attempts to reload the restored configuration.
6. **Update operations lacked a non-destructive preview.** A new `--dry-run` option reports planned changes and conflicts without modifying files or reloading services.
7. **Installer behavior lacked dedicated regression coverage.** Added offline tests for fresh installs, repeat installs, supported upgrades, retained jail settings, custom signatures, safe merges, detected conflicts, local overrides, dry runs, symlinks, and rollback.

## Upgrade instructions

Download the v1.3.1 release archive, extract it, and run from its top-level directory:

```bash
sudo bash ./install/install.sh --dry-run
sudo bash ./install/install.sh
sudo fail2ban-client -t
sudo fail2ban-client status
```

Review the dry-run output before applying changes. Existing jail settings, including custom `maxretry`, `findtime`, `bantime`, and `logpath`, are preserved.

## Compatibility and limitations

- Supports automatic upgrade of unmodified filters from v1.2.1 and v1.3.0. Non-conflicting custom changes may be merged; uncertain or conflicting changes require manual review.
- If the MiniSOC configuration directory is absent, the signature database step is skipped. Use `MINISOC_REQUIRED=1` to treat its absence as an error.
- The MiniSOC application is **not restarted** and may need a separate signature-cache reload, depending on its implementation.
- This repository updates rules and signatures, **not** the MiniSOC application classifier or alert formatting code.
- No changes are applied to a production server by publishing this release.

## Verification

The release includes ten installer regression tests and the repository's existing signature regression checks. These are offline tests; administrators should still validate against their own Nginx logs and Fail2Ban configuration before deployment.

Thank you to everyone who reports issues and contributes to safer, more reliable community detection rules.
