# MiniSOC Fail2Ban Rules v1.3.2

**Maintenance and detection update — 21 November 2026**

## Why this release was published

Version 1.3.2 addresses defects found during a review of the v1.3.1 installer, uninstaller, rollback procedures, and rule-validation process. The main goal is to make upgrades safer for existing Fail2Ban installations while improving detection of high-confidence secret-discovery probes observed in November 2026. Broad or ambiguous requests remain review-only to limit false positives.

## Bugs fixed

- **Unsafe uninstall behavior:** replaced unconditional removal with a conservative uninstaller that refuses to delete customized filters, jail definitions, or files with local overrides. It backs up project-managed files and restores them if validation or service reload fails.
- **Incomplete rollback and recovery:** added version-aware upgrade baselines, protected backup manifests, SHA-256 checks, original ownership and permission metadata, and a guarded manual restore command.
- **Configuration-loss risk during updates:** preserve existing jail settings and operator-defined MiniSOC signatures; reject conflicting signature IDs, symlinks, unknown local modifications, and ambiguous filter merges before writing.
- **Misleading regex validation:** require actual `fail2ban-regex` matches on malicious fixtures and zero matches on benign fixtures. GitHub validation and release jobs install the real parser and fail if these checks do not pass.
- **Request-target false positives:** narrow active Nginx expressions to avoid banning benign requests solely because a suspicious filename appears in an unrelated query parameter.
- **Duplicate incident counts:** distinguish jail notifications, total displayed requests, deduplicated HTTP events, and unique request targets in the incident-correlation utility.

## Detection improvements

- Added precise signatures for encoded or double-encoded `.env` discovery, selected traversal variants, sensitive application credential paths, and exact root SQL backup names.
- Extended exact repository metadata and secret-file coverage, including service-account credentials and Streamlit secrets.
- Added sanitized regression fixtures and reviewed incident evidence through 21 November 2026.
- Kept generic `config.json`, ordinary frontend JavaScript, broad WordPress reconnaissance, and unverified API file-read probes in non-blocking review categories.
- HTTP status changes for the same IP/path and equivalent encoded targets are **diagnostic signals only**; they do not independently cause bans.

## Validation

- 10 existing updater regression tests and 39 additional offline tests passed.
- The GitHub Actions validation workflow also passed using a real Fail2Ban parser on the release candidate.
- Automated release validation requires the same real-parser checks before creating versioned archives.
- The released source includes all original project files and the v1.3.2 changes; it is not a partial overlay.

## Recommended update procedure

From a verified checkout or extracted official release archive:

```bash
sudo bash ./install/install.sh --dry-run
sudo bash ./install/install.sh
sudo fail2ban-client -t
sudo fail2ban-client status
```

To inspect a particular backup without changing the system:

```bash
sudo python3 install/restore_backup.py /etc/fail2ban/minisoc-backup-YYYYMMDDTHHMMSSZ-PID --dry-run
```

Use the exact backup directory printed by the installer. Remove `--dry-run` only after reviewing the restore plan. Keep an administrative console available for recovery.

## Compatibility and important limitations

- Intended for Linux installations with Nginx and Fail2Ban; changes are applied only when the operator runs the installer.
- The updater manages the bundled `nginx-skanery` and `nginx-dev-honeypot` filters and their example jail. It does **not** replace custom `nginx-highconf` or `nginx-fake-searchbots` jail configurations.
- Conflicting or unknown local configurations require manual review. Never force an overwrite to bypass the safety checks.
- The standalone MiniSOC application, its Telegram classification service, and any in-memory signature cache are **not** restarted or updated by this package.
- The project's CI tests cannot prove compatibility with every production Nginx log format or downstream MiniSOC integration; validate your host before applying the update.

For full operating guidance, see the [Fail2Ban operating guide](https://github.com/myselfhosted-online/minisoc-fail2ban-rules/blob/v1.3.2/docs/FAIL2BAN.md).
